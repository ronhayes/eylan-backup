# پشتیبان Eylan برای Ubuntu 22.04

**نسخه آزمایشی؛ روی سرور اصلی نصب یا اجرا نشود.** آزمون سرتاسری ارسال تلگرام و ریستور PostgreSQL در Ubuntu هنوز انجام نشده است. پیش از استفاده، کل مسیر بازیابی را در سرور آزمایشی بررسی کنید.

این ابزار نسخه رمزگذاری‌شده دیتابیس `eylan_panel` و فایل‌های شناسایی‌شده پنل را محلی نگه می‌دارد و ساعتی به Telegram می‌فرستد. کامل بودن فهرست فایل‌ها تضمین نمی‌شود؛ مسیرهای نصب خود را بررسی و در صورت نیاز جداگانه پشتیبان بگیرید. سرور قبلی تغییر نمی‌کند.

## پیش‌نیاز و راه‌اندازی

روی سرور مقصد با دسترسی root اجرا کنید. ابزارهای `systemd`, `gpg`, `openssl`, `python3`, `curl`, `tar`, `flock` و کلاینت PostgreSQL لازم‌اند؛ کاربر سیستم `postgres`، دیتابیس و نقش `eylan_user` باید موجود باشند. دسترسی مدیر محلی PostgreSQL برای `postgres` لازم است.

برای دریافت اسکریپت و بازشدن خودکار منو روی **سرور آزمایشی**، دستور زیر را اجرا کنید. این دستور کد شاخه `main` را بلافاصله با دسترسی مدیر اجرا می‌کند؛ پیش از اجرا به محتوای مخزن اعتماد کنید:

```bash
f=$(mktemp) && curl -fsSL https://raw.githubusercontent.com/ronhayes/eylan-backup/main/eylan-backup.sh -o "$f" && sudo bash "$f"
```

برای بررسی اسکریپت پیش از اجرا، به‌جای دستور بالا آن را جداگانه دانلود کنید، محتوایش را ببینید و سپس با `sudo bash` اجرا کنید.

پس از نصب، برای اجرای دوباره منو:

```bash
sudo /usr/local/sbin/eylan-backup
```

گزینه ۱ را انتخاب کنید و توکن ربات و شناسه عددی چت را وارد کنید. ابتدا به ربات پیام بدهید و دسترسی آن به چت را بررسی کنید. نصب پس از تأیید، تایمر `eylan-backup.timer` را فعال می‌کند. وضعیت و خطاها:

```bash
sudo systemctl status eylan-backup.timer
sudo journalctl -u eylan-backup.service -n 100 --no-pager
sudo systemctl start eylan-backup.service
```

توکن در `/etc/eylan-backup/telegram` و کلید در `/etc/eylan-backup/passphrase` با دسترسی root نگهداری می‌شوند؛ آنها را منتشر نکنید. **از کلید جداگانه و امن خارج از سرور نسخه بگیرید**؛ بدون همان کلید بازیابی ممکن نیست. روی سرور مقصد پیش از بازیابی، همان کلید را در مسیر فوق با مالک root و دسترسی `600` قرار دهید. هرگز آن را در Telegram یا مخزن عمومی قرار ندهید. رمزگذاری محتوای فایل‌ها از جمله کلیدهای خصوصی را پیش از ذخیره و ارسال پوشش می‌دهد.

نسخه‌های رمزگذاری‌شده در `/var/backups/eylan-backup` بدون حذف خودکار انباشته می‌شوند؛ با رسیدن به ۴۸ نسخه، پشتیبان‌گیری خودکار تا حذف دستی نسخه‌های اضافی متوقف می‌شود. فضای دیسک را نیز پایش کنید؛ این سقف تعداد، مصرف فضا را محدود نمی‌کند. ارسال‌های بیش از ۴۹٬۰۰۰٬۰۰۰ بایت برای محدودیت Bot API رد می‌شوند، اما نسخه محلی حفظ می‌شود. خطاهای ارسال و پاسخ API در وضعیت سرویس ثبت می‌شوند. نام و اندازه فایل ارسالی برای Telegram قابل مشاهده است.

## بازیابی

گزینه ۲ را اجرا، مسیر کامل فایل `.tar.gz.gpg` محلی و تأییدهای خواسته‌شده را وارد کنید. ابتدا کلید اصلی را روی مقصد قرار دهید. فقط نسخه‌ای را بازیابی کنید که به سازنده آن اعتماد دارید: dump دیتابیس می‌تواند SQL دلخواه اجرا کند. یک دیتابیس موقت با مالک `eylan_user` ساخته و dump در آن بارگذاری می‌شود. سپس فقط `openvpn_manager.service` در صورت فعال بودن متوقف، یک dump رمزگذاری‌شده از دیتابیس فعلی گرفته، دیتابیس‌ها جابه‌جا و سرویس دوباره راه‌اندازی می‌شود. دیتابیس قدیمی با نام `eylan_old_...` و نسخه پیش از بازیابی حفظ می‌شوند؛ در شکست، پیام خطا و نام‌ها را بررسی کنید. اگر اتصال دیگری به دیتابیس برقرار باشد، جابه‌جایی شکست می‌خورد؛ اسکریپت آن اتصال را قطع نمی‌کند. ابتدا همه نویسنده‌های دیتابیس را خودتان متوقف کنید.

**هیچ فایل پیکربندی خودکار جایگزین نمی‌شود.** فایل‌ها در `/root/eylan-recovery-.../files` برای بررسی دستی قرار می‌گیرند. مالکیت، سطح دسترسی و زمان فایل‌ها در پوشه بازیابی حفظ نمی‌شوند؛ این موارد، لینک‌ها، مسیر گواهی‌ها و سازگاری سیستم مقصد را پیش از هر کپی دستی بررسی کنید؛ تنظیمات میزبان مانند `/etc/sysctl.d` ممکن است مختص سرور قبلی باشند. لینک‌های نمادین و فایل‌های ویژه پشتیبان‌گیری نمی‌شوند؛ به‌ویژه لینک‌های Let's Encrypt ممکن است نیاز به بازسازی دستی داشته باشند. فایل dump رمزگشایی‌شده و فایل‌های بازیابی در این پوشه فقط برای root قابل دسترسی‌اند، ولی روی دیسک باقی می‌مانند؛ پس از اطمینان، مطابق سیاست امنیتی خود حذفشان کنید.

بایگانی شامل مسیرهای تنظیمات پنل در `/root`، OpenVPN، ocserv، IPsec/strongSwan، xl2tpd، PPP، WireGuard، sing-box، گواهی‌ها، تنظیمات sysctl و واحد سرویس پنل است. فایل‌های ناموجود در گزارش ثبت می‌شوند؛ این فهرست جایگزین بررسی نصب و آزمایش بازیابی نیست.
